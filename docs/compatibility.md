# 规则差异和部署条件

## 任务模式先明确

成稿整体锁定扩图与分层重新构图不能同时执行。`baseedge-cover-production` 的成稿模式只允许整体等比例变换；`cover-dimensions` 和 responsive 的正文仍保留独立场景重构流程。最新共享参考要求根据用户的明确锁定或局部重排反馈选择模式。本发布保留原文，未擅自改写为统一算法。

## 尚未统一的规则

| 项目 | 来源差异 | 使用时如何处理 |
| --- | --- | --- |
| 期号 | production 全部禁用；dimensions 按配置；human 竖版及视频号原型保留 | 读取项目配置并落实当前用户要求，不混用流程 |
| Logo | production 主文引用包内两张 Logo；dimensions 指定本机十二张平台定位模板 | 按任务所用流程和批准资产执行；包内两张图不能代替十二张定位模板 |
| 公众号安全区 | human 与 production 特定人物案例给出不同坐标 | 确认适用案例和批准参考，勿直接推广案例坐标 |
| 失败候选交付 | dimensions 禁止强行交付不合格结果；single-product 旧参考有三次审核后发送候选图的规则；新共享参考区分用户要求发修订稿与整套合格 | 明确候选稿与最终稿状态；对外发送仍需用户授权，不能将待复核宣称合格 |
| 装饰删除 | 部分旧条目称装饰 optional；最新共享规则强调有意设计的装饰默认保留 | 记录保留清单和删除依据，用户指出遗漏的元素必须保留 |

## 环境条件

- 技能原文中的 `F:\橙子\封面logo\白logo\`、`黑logo\` 等是原环境路径，不是本包提供的目录。部署时配置实际批准资产，不能假定磁盘路径可用。
- 项目 JSON、React/Konva 编辑器、机器人接单服务、进度同步服务不在此包内。
- 共享参考的 `<FEISHU_PROGRESS_DOCUMENT_URL>` 与 `<FEISHU_COVER_CHAT_ID>` 需由部署者在本地私有配置或副本中替换。不要把实际值提交回公开仓库。
- 图像生成工具、字体、批准参考图和原始素材需要按具体任务准备。
- 各个技能有配套引用，建议四个目录一起安装。

仅记录现状与可复用流程；此次整理未修改本机已安装的 skills，也未部署运行时服务。
